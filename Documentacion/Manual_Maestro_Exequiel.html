01. Integración al Proyecto y Onboarding

Flujo de sincronización de código y levantamiento de entorno local para Exequiel.

¡Bienvenido al flujo de desarrollo, Exequiel! Esta guía de onboarding te permitirá sincronizar tu base de código local y preparar el entorno de forma automatizada junto a tu asistente **Antigravity**.

⚠️ Sincronización del Código de la Cátedra (Git checkout)

Para evitar pisar código y mantener la disciplina pactada con la IA, debes sincronizarte a la rama compartida dev ejecutando de forma estricta los siguientes comandos en tu consola local:

# 1. Cambiarse a la rama principal y descargar los últimos cambios
git checkout main
git fetch origin

# 2. Sincronizarse a la rama dev del equipo
git checkout dev
git pull --rebase origin dev

⚙️ Configuración del Entorno de Desarrollo

Dado que cuentas con **Antigravity** instalado, el levantamiento de dependencias y base de datos está totalmente automatizado en tu máquina local. Los pasos lógicos estructurados son:

1

Restaurar Base de Datos

Ejecutar el proyecto migrador en aspnet-core/src/TourismTracking.DbMigrator/. Creará la base de datos física local en SQL Server y cargará las semillas iniciales.

2

Levantar Backend (.NET)

Ejecutar dotnet run en TourismTracking.HttpApi.Host/ para iniciar el servidor Web API (puerto 44305).

3

Levantar Frontend (Angular)

Ingresar a angular/, ejecutar npm install y arrancar la UI web con npm start (puerto 4200).

02. El Protocolo de Colaboración Git-AI

Reglas estrictas para subir cambios a la rama dev compartida de forma segura.

Trabajar de forma dinámica sobre una misma rama dev requiere de un protocolo riguroso. Este flujo garantiza que el código de la nube nunca se rompa y que las IAs resuelvan cualquier conflicto de forma lógica.

➔

Push Seguro
🏁 Reglas del Commit Seguro

Antes de que la IA suba un push a dev, debe ejecutar obligatoriamente de forma local la compilación (dotnet build) y pasar los tests (dotnet test). Si hay algún error, el push se aborta de inmediato.

🧬 Resolución de Conflictos

En caso de conflictos en rebases, la IA no debe descartar los cambios del compañero ciegamente. Analizará la intención leyendo el git log y propondrá una fusión lógica funcional.

💻 Secuencia de Integración Local Obligatoria

Este es el comando a ejecutar por la IA para integrar y subir cambios de manera segura:

# 1. Sincronizar local con cambios remotos en dev
git pull --rebase origin dev

# 2. Validar integridad de compilación
dotnet build aspnet-core/TourismTracking.sln

# 3. Validar estabilidad de lógica de negocio (Tests)
dotnet test aspnet-core/TourismTracking.sln

# 4. Crear commit semántico y subir
git add .
git commit -m "feat(destination): cache popular destinations to local database"
git push origin dev
🛡️ Protección del Código de Entrega (Rama 'prod')

La rama prod está protegida en GitHub. Todo cambio debe realizarse mediante Pull Request (PR) automáticos preparados por la IA desde dev, detallando el Changelog técnico académico.

03. Spec-Driven Development (SDD)

Uso de contratos en backend como única fuente de verdad (Single Source of Truth).

El Desarrollo Guiado por Especificaciones (SDD) garantiza la consistencia total entre Backend y Frontend. Al definir los contratos primero, Angular se acopla dinámicamente mediante proxies, eliminando la escritura manual de llamadas HTTP y DTOs.

Contrato C# (.Contracts)
➔
Compilar Backend (dotnet build)
➔
Generar Proxies (abp CLI)
📏 Pasos para la Creación de Endpoints y UI en Angular
  1. Crear Contrato en Backend: Escribir los DTOs y la interfaz del servicio (ej. IDestinationAppService) en el proyecto TourismTracking.Application.Contracts.
  2. Compilar la Solución: Ejecutar dotnet build en C# para actualizar la metadata local.
  3. Autogenerar los Proxies en Angular: Abrir la consola en la carpeta angular/ y ejecutar: 
    abp generate-proxy -t ng
  4. Consumir el Servicio: Angular tendrá automáticamente inyectable el nuevo servicio con todos sus DTOs tipados en TypeScript, listos para integrarse en tus componentes UI.
🎓 Justificación Académica ante el Tribunal

"Utilizamos Spec-Driven Development bajo la CLI de ABP para garantizar que no existan inconsistencias de tipado o errores ortográficos en la comunicación API. Esto permite un acoplamiento limpio y desacoplado, permitiendo que el Frontend y el Backend avancen en paralelo basándose exclusivamente en el contrato DTO."

04. Manual de Interacción con Antigravity & Skills

Inyección de habilidades y alineamiento del asistente inteligente en tu entorno.

Para acelerar el desarrollo del proyecto, debes configurar a tu asistente de IA (**Antigravity**) instalando las dos Skills de desarrollo de forma global. Esto inyectará los protocolos de Git-AI y SDD directamente en su motor lógico.

📂 Procedimiento de Instalación de Skills (Paso a Paso)
  1. Copia la carpeta skills/ provista en este paquete de descargas (que contiene los directorios git-ai-collaboration y spec-driven-development).
  2. Pégala en el directorio de configuración global de Gemini en tu perfil de usuario de Windows (reemplaza por tu nombre de usuario de Windows): 
    C:\Users\<TuUsuarioWindows>\.gemini\config\skills\
  3. ¡Listo! Al abrir Antigravity y arrancar la sesión, el agente cargará estas directivas de manera transparente como habilidades operacionales nativas.
