02. El Protocolo de Colaboración Git-AI

Para evitar colisiones de código y conflictos al trabajar en paralelo sobre la misma rama dev de integración, hemos diseñado un protocolo estricto ("Git-AI Protocol"). Este protocolo debe ser cumplido rigurosamente tanto por nosotros como por las IAs.

Pull & Rebase (dev)
➔
Validar Local (Build & Test)
➔
Commit Semántico
➔
Push Seguro (dev)

📝 El Algoritmo de Commit y Push

Cada vez que tu IA o tú realicen un cambio funcional en la base de código, se debe verificar localmente la estabilidad del sistema antes de subirlo a la rama remota:

# 1. Traer cambios más recientes
git pull --rebase origin dev

# 2. Compilar el Backend para asegurar que no hay errores
dotnet build aspnet-core/TourismTracking.sln

# 3. Ejecutar las pruebas unitarias y de integración
dotnet test aspnet-core/TourismTracking.sln

# 4. Crear commit semántico si todo pasa
git add .
git commit -m "feat(interaction): add average rating calculations"

# 5. Push seguro a la rama de desarrollo
git push origin dev
🔒 Protección de Producción (Rama 'prod') La rama de entrega final y defensa de cátedra (prod) está protegida contra empujes directos. Todo despliegue a producción se realiza mediante **Pull Requests** generados automáticamente por la IA desde dev, previa compilación exitosa del 100% de la suite.

03. Spec-Driven Development (SDD)

El Desarrollo Guiado por Especificaciones (SDD) garantiza la sincronización perfecta y sin errores ortográficos de tipos de datos entre el Frontend (Angular) y el Backend (C# .NET) a través de la autogeneración de proxies de ABP.

Definir Contrato (.Application.Contracts)
➔
Compilar Backend (dotnet build)
➔
Generar Proxies (abp generate-proxy)

🛠️ Flujo de Trabajo Contract-First

Queda estrictamente prohibido picar a mano llamadas HttpClient en Angular. El pipeline oficial a seguir por IAs y humanos es el siguiente:

  1. Contrato en C#: Define las firmas de servicio e interfaces en el proyecto TourismTracking.Application.Contracts (ej. IDestinationAppService.cs) junto con sus respectivos DTOs de entrada y salida.
  2. Compilación: Compila el backend ejecutando dotnet build para regenerar el catálogo de metadata.
  3. Proxy angular: Desde la terminal dentro del directorio angular/, ejecuta: 
    abp generate-proxy -t ng
    Esto autogenerará los archivos TypeScript tipados en angular/src/app/proxy/.
  4. Consumo: Inyecta el servicio generado en tu componente de Angular y consúmelo nativamente.
💡 Ventajas para la Defensa Académica

Este flujo permite justificar ante los evaluadores un acoplamiento limpio de capas y el uso del patrón **Single Source of Truth** (Contrato de API único), acelerando el desarrollo en paralelo y reduciendo errores ortográficos en la comunicación de red.

04. Manual de Interacción con Antigravity

Para potenciar el par-programming, debes configurar a tu asistente de IA (**Antigravity**) instalando las Skills del proyecto de forma global en tu máquina de desarrollo. Esto permitirá que la IA entienda y aplique automáticamente todas las reglas de Git y SDD explicadas en este manual.

📂 Instalación de las Skills (Paso a Paso)

Las Skills son conjuntos de instrucciones estructuradas en Markdown y configuraciones que guían de forma estricta el comportamiento del agente.

⚙️ Procedimiento de Instalación Local
  1. Copia la carpeta skills/ provista en este paquete de descargas (que contiene git-ai-collaboration y spec-driven-development).
  2. Pégala en el directorio de configuración global de Gemini en tu perfil de usuario de Windows: 
    C:\Users\<TuNombreUsuarioWindows>\.gemini\config\skills\
  3. **Listo!** Al abrir Antigravity y arrancar la sesión, el agente cargará estas directivas como habilidades de forma transparente.

🤖 Cómo alimentar a la IA con Contexto

Una vez que te sincronices con la rama dev de Git e instales las skills globales, abre el chat con tu IA en el editor de código y proporciónale el siguiente prompt base para alinear sus objetivos de inmediato:
